# Publishing

The release workflow for cutting a new version to Packagist.

## Before you tag

Run the full quality gate and make sure it is green:

```bash
composer test       # pest — keep the end-to-end test green
composer analyse    # phpstan / larastan level 5
composer format     # laravel pint
```

## Steps

1. **Commit your changes.** Do **not** hand-edit `CHANGELOG.md` — it is generated by the
   changelog workflow.

   ```bash
   git commit -am "fix: ..."
   git push
   ```

2. **Tag with no `v` prefix.** This package uses bare semver tags (e.g. `1.0.0`, not `v1.0.0`).

   ```bash
   git tag 1.0.0
   git push origin 1.0.0
   ```

3. **Create the GitHub release** for that tag (the changelog workflow fills in the notes).

   ```bash
   gh release create 1.0.0 --generate-notes
   ```

## Packagist

Packagist updates automatically via the GitHub service hook when the tag is pushed. If a release
does not appear, trigger an update from the package page on Packagist, or check the configured
webhook.

## Versioning

Follow [semantic versioning](https://semver.org):

- **patch** (`1.0.x`) — bug fixes, no API change
- **minor** (`1.x.0`) — backwards-compatible features
- **major** (`x.0.0`) — breaking changes (e.g. dropping a Laravel/PHP version, renaming config
  keys or the Livewire component name)
